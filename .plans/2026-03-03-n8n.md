# n8n Custom Node Integration

El objetivo es crear un "Custom Node" ([Documentación n8n](https://docs.n8n.io/integrations/creating-nodes/build/)) para que HorneroDB pueda ser arrastrado visualmente dentro de los flujos de n8n. Esto permitirá tanto Acciones (CRUD) como Gatillos (Webhooks).

## Estructura del Nodo (NPM Package)

Para n8n, se creará un paquete NPM completo (típicamente llamado `n8n-nodes-hornerodb`).
Este paquete vivirá dentro de `/misc/connectors/n8n/`.

Requeriremos inicializar:
- `package.json`
- `tsconfig.json`
- `gulpfile.js`
- Directorio de credenciales: `credentials/HorneroDBApi.credentials.ts` y `credentials/HorneroDBOAuth2Api.credentials.ts`
- Nodos operativos: `nodes/HorneroDB/HorneroDB.node.ts`
- Nodos reactivos (Triggers): `nodes/HorneroDBTrigger/HorneroDBTrigger.node.ts`

## 1. Credenciales Múltiples

A diferencia de PowerAutomate, n8n maneja muy bien la multiplicidad de credenciales en un mismo nodo.
1. **API Key (`HorneroDBApi.credentials.ts`)**:
   Pediremos al usuario su Host de Servidor (URL) y el API Key. El nodo inyectará automáticamente el header `Authorization: Bearer <API_KEY>`.
2. **PocketID OAuth2 (`HorneroDBOAuth2Api.credentials.ts`)**:
   Usaremos el tipo de credencial OAuth2 nativo de n8n. El usuario configurará el *Client ID*, *Client Secret*, y las URLs de Token y Autorización de su PocketID. El nodo inyectará el Token final.

## 2. HorneroDB Regular Node (Activo)

`HorneroDB.node.ts` implementará la interfaz `INodeType`.
Permitirá seleccionar:
- **Resource (Recurso)**:
  - `Workspace`: Listar.
  - `Table`: Listar.
  - `Record`: Crear, Leer, Actualizar, Borrar, Listar (con paginación y filtros OData o params nativos).
- **Operations (Operaciones)**: Dependerán del Recurso seleccionado.
- **Campos dinámicos**: Cuando el usuario seleccione un *Workspace* y una *Table*, el nodo hará un `GET` a la API de columnas (`/workspaces/:w/tables/:t/columns`) para recuperar los campos disponibles y pintar el formulario visual (UI dinámico) de la fila. Esto hará que la UX sea de primera clase.

## 3. HorneroDB Trigger Node (Reactivo / Webhooks)

`HorneroDBTrigger.node.ts` implementará los métodos de ciclo de vida de n8n Webhooks:
- `webhookMethods.default.checkExists`: Verifica si ya estamos suscritos consultando `GET /api/v1/workspaces/:ws/webhooks`.
- `webhookMethods.default.create`: Registra el flujo de n8n usando nuestro nuevo sistema (`POST /api/v1/workspaces/:ws/webhooks`). Usa la *Webhook URL* de n8n como payload y `client_state` para seguridad.
- `webhookMethods.default.delete`: Limpia la suscripción al apagar el flujo (`DELETE /webhooks/:id`).

Esta arquitectura asegurará ejecución *instantánea* e inteligente sin polling costoso.
