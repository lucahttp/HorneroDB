# Webhooks (MS Graph API Style)

**El objetivo es proveer a HorneroDB de un sistema de subscripciones/notificaciones push (Webhooks) al estilo de Microsoft Graph**. Esto es **crucial** y el paso número uno antes de construir los conectores de n8n, Typebot o PowerAutomate, ya que estos conectores necesitarán triggers (Gatillos) que escuchen cada vez que una fila sea creada, actualizada o borrada en HorneroDB.

## Arquitectura

Se propone crear una tabla metadata para los webhooks, basándonos en los [recursos de suscripción de MS Graph](https://learn.microsoft.com/en-us/graph/api/resources/subscription?view=graph-rest-1.0).

### 1. Tabla: `_hornero_webhooks` (Modelo)
- `id` (UUID, PK)
- `workspace_id` (UUID) - A qué Workspace pertenece
- `resource` (UUID) - El ID de la tabla que se está observando. Se triggereará *únicamente* cuando se cree, modifique o borre una fila (row) en esta tabla específica.
- `change_type` (String) - Múltiple con comas: `created,updated,deleted`
- `notification_url` (String) - Donde HorneroDB enviará el POST http.
- `client_state` (String) - Secreto opcional; HorneroDB lo enviará como Header/Payload para que el cliente (n8n/zapier) valide el origen auténtico.
- `expires_at` (Timestamp, opcional) - Expiración de la subscripción (requiere un servicio de renovación como en MS Graph).
- `created_at` (Timestamp)
- `created_by` (String) - Quién creó el webhook

### 2. Endpoints API
Se requerirán endpoints CRUD similares a MS Graph bajo cada workspace:
- `GET /api/v1/workspaces/:workspace_id/webhooks`
- `POST /api/v1/workspaces/:workspace_id/webhooks`
- `GET /api/v1/workspaces/:workspace_id/webhooks/:webhook_id`
- `PATCH /api/v1/workspaces/:workspace_id/webhooks/:webhook_id` (para renovar expires_at)
- `DELETE /api/v1/workspaces/:workspace_id/webhooks/:webhook_id`

### 3. Worker de Ejecución (Golang Async)
Para evitar trabar las peticiones de los usuarios:
1. Al crear/actualizar/borrar un record en `api/data.go`, se lanzará una rutina de Go: `go webhooks.Dispatch(workspaceID, resource, action, payload)`
2. Esa rutina verificará los webhooks activos para ese evento en la BD.
3. Enviará una ráfaga de POST en paralelo para todas las URLs registradas con el payload del objeto (tipo MS Graph `value: []`).
