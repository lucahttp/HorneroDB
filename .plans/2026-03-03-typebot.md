# Typebot Connector Integration

El objetivo es crear un bloque de integración personalizado para [Typebot (usando The Forge)](https://docs.typebot.io/contribute/the-forge/overview) que permita a los chatbots conversacionales leer y escribir datos en HorneroDB.

## Estructura del Bloque (Forge)

Typebot permite a los desarrolladores crear integraciones que los usuarios pueden arrastrar y soltar en el constructor de bots. El código vive en el repositorio principal de Typebot (o en un fork) en la carpeta `packages/forge/blocks/hornerodb/`.

Estructuraremos nuestra integración de la siguiente manera:
1.  **Directorio Base**: `packages/forge/blocks/hornerodb`
2.  **`index.ts`**: Define los metadatos del bloque (nombre, logo, color, auth).
3.  **Auth (Autenticación)**: Typebot maneja la autenticación globalmente por integración.
4.  **Acciones (Actions)**: Cada operación (Insertar Fila, Buscar Fila) será un archivo separado importado en el índice.

## 1. Autenticación Global (API Key)

Para Typebot, la forma más sencilla y robusta de conectar flujos conversacionales no atendidos a una base de datos es mediante **API Keys** a nivel de Workspace. OAuth suele requerir una UI interactiva que no tiene sentido para un bot que corre en el fondo.

En `index.ts`, definiremos el requerimiento de Auth:
-   `auth: { type: 'encrypted', name: 'API Key', inputs: [...] }`
-   Pediremos dos inputs: `Host URL` (ej. `https://api.hornerodb.com`) y el `API Key`.

## 2. Acciones del Bloque (Actions)

Implementaremos acciones específicas que los constructores de bots necesitan más. Al igual que con n8n, haremos un esfuerzo por usar campos dinámicos para mejorar la Developer Experience (DX).

### Acción: Insert Record (`actions/insertRecord.ts`)
1.  **Inputs Estáticos**: `Workspace ID` y `Table Slug`. (Typebot permite inputs de tipo dropdown que pueden fetchear estas opciones de la API usando `fetchers`).
2.  **Campos Dinámicos**: En Typebot, si el usuario selecciona una Tabla, podemos usar un bloque dinámico para renderizar campos visuales correspondientes a las columnas de esa tabla.
3.  **Ejecución**: En `run`, enviaremos un POST a `/api/v1/workspaces/:wId/data/:tableSlug`.

### Acción: Get Record (`actions/getRecord.ts`)
1.  **Inputs**: `Workspace ID`, `Table Slug`, `Record ID`.
2.  **Ejecución**: Enviaremos un GET a `/api/v1/workspaces/:wId/data/:tableSlug/:recordID`.
3.  **Salida (Output)**: En Typebot, mapearemos el JSON de respuesta a las variables del bot para que puedan usarse en mensajes subsecuentes.

### Acción: Search Records (`actions/searchRecords.ts`)
1.  **Inputs**: `Workspace ID`, `Table Slug`, Parámetros de búsqueda (OData/Querystring).
2.  **Ejecución**: List records GET Endpoint.
3.  **Salida**: Array de resultados para iterar en el bot.
